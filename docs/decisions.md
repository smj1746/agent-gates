# 설계 결정 기록

결정마다 무엇을 골랐는지, 왜 골랐는지, 무엇을 포기했는지를 남깁니다.
바꾸고 싶은 결정이 있으면 이 문서를 먼저 고친 뒤 코드를 바꿉니다.

---

## D-1. 런타임 의존성을 두지 않는다

- **결정**: 실행에 필요한 패키지는 0개. 인자 처리는 Node 내장 `util.parseArgs`, 글롭은 `src/core/glob.ts`에 직접 구현.
- **이유**: 저장소 규칙을 검사하는 도구는 오래, 여러 저장소에서 같은 결과를 내야 합니다. 의존성이 없으면 설치가 빠르고(`npx github:` 실행 포함), 다른 패키지의 변경이나 보안 경고에 휘둘리지 않습니다.
- **포기한 것**: `picomatch` 같은 라이브러리의 풍부한 글롭 문법(부정 `!`, 문자 범위 `[a-z]`, 중첩 중괄호). 필요한 문법만 지원하고 테스트로 고정했습니다.

## D-2. Node 22.12 이상만 지원한다

- **결정**: `engines.node >=22.12`, CI는 Node 22와 24.
- **이유**: Node 20은 2026년 4월에 지원이 끝났습니다. 테스트 도구(Vitest 5)도 22.12 이상을 요구합니다.
- **포기한 것**: 오래된 Node를 쓰는 저장소.

## D-3. 글롭은 경로 전체와 비교한다

- **결정**: `*.md`는 루트 파일만, `**/*.md`는 모든 폴더. (gitignore처럼 '슬래시 없는 패턴은 어디서나'로 바꾸지 않음)
- **이유**: 규칙이 하나면 설정을 읽는 사람과 에이전트가 같은 뜻으로 이해합니다. 담당표(`scope.owners`)는 경로를 정확히 가리켜야 해서 특히 중요합니다.
- **포기한 것**: gitignore에 익숙한 사람의 직관. 문서와 도움말에 예를 들어 적었습니다.

## D-4. 표식 검사는 Markdown을 기본으로 뺀다

- **결정**: `markers.exclude` 기본값에 `**/*.md`. 설정 파일과 게이트 파일은 설정과 상관없이 늘 뺌.
- **이유**: `AGENTS.md`·`CLAUDE.md`는 "미정 값은 `TODO(확인필요)`로 남긴다"처럼 표식 글자를 **규칙으로** 담고 있습니다. 이걸 세면 진짜 미정 사항과 섞입니다.
- **포기한 것**: 문서 안의 진짜 미정 표식. 필요하면 `exclude`를 고쳐 넣을 수 있습니다.

## D-5. 미정 표식은 기준이 있을 때만 실패시킨다

- **결정**: `markers.max`의 기본값은 `null`(개수만 알림).
- **이유**: 표식은 '없애야 할 것'이 아니라 '드러나 있어야 할 것'입니다. 처음부터 실패시키면 사람과 에이전트가 표식을 지우는 쪽으로 움직여, 오히려 미정 사항이 숨습니다. 팀이 기준을 정한 뒤에 `max`로 조입니다.

## D-6. 게이트는 '제목 + 칸 목록' 형식 하나만 읽는다

- **결정**: `## G-숫자 | 제목` 아래 `- 칸: 값`. 필수 칸은 상태 · 발생 상황 · 금지 경로 · 대신 할 것.
- **이유**: 실제로 운영한 게이트(해커톤 프론트엔드 G-1)가 이 형식이었고, 사람이 읽기 쉬우면서 에이전트가 같은 모양으로 초안을 쓰기 쉽습니다. '금지 경로'와 '대신 할 것'이 둘 다 있어야 다음 작업자가 같은 실수를 피하고 갈 길을 압니다.
- **포기한 것**: 표 형식이나 YAML 앞부분(front matter). 칸 이름이 프로젝트마다 다를 수 있어 `aliases`와 `required`/`optional`만 설정으로 열었습니다.

## D-7. 주석과 코드 블록 안은 읽지 않는다

- **결정**: `<!-- -->`와 ` ``` `·`~~~` 안의 게이트 제목은 무시. 지울 때 줄바꿈은 남겨 줄 번호를 원문과 맞춤.
- **이유**: 게이트 문서 맨 위에 형식 예시를 두는 경우가 많습니다. 예시를 게이트로 세면 늘 형식 오류가 납니다.

## D-8. 담당 범위는 '다른 담당'만 실패시킨다

- **결정**: 다른 담당자의 파일 = 오류, 공유 파일 · 담당표에 없는 파일 = 경고.
- **이유**: 실제 팀 규칙은 "담당 밖 파일을 고쳐야 하면 **멈추고 알린다**"였습니다. 막을 것(남의 화면을 고침)과 알릴 것(공유 파일, 아직 담당이 없는 파일)을 나눠야 규칙이 일상적으로 지켜집니다. 경고까지 실패시키면 사람들이 검사를 끕니다.
- **포기한 것**: 공유 파일을 화면 PR에 섞는 것을 강제로 막는 기능. 필요하면 다음 버전에서 옵션으로 둡니다.

## D-9. `init`은 덮어쓰지 않는다

- **결정**: 파일을 `wx` 플래그로 만들어, 있으면 건너뜀. `--force` 옵션도 두지 않음.
- **이유**: 사람이 쓴 규칙 문서를 도구가 지우면 안 됩니다. `AGENTS.md`가 이미 있으면 붙여 넣을 규칙을 화면에 보여 주는 것으로 대신합니다.

## D-10. 종료 코드를 셋으로 나눈다

- **결정**: `0` 통과 · `1` 규칙 위반 · `2` 사용법·설정·실행 환경 오류.
- **이유**: CI에서 "규칙을 어겼다"와 "검사를 못 했다"를 구분해야 고칠 사람이 달라집니다. 설정 오류는 한 번에 모아 보여 줍니다.

## D-11. 출력은 사람용 텍스트와 JSON 두 가지, 색은 쓰지 않는다

- **결정**: 기본은 한국어 텍스트, `--json`은 같은 정보를 그대로. ANSI 색 없음.
- **이유**: 사람은 텍스트를, 에이전트와 CI는 JSON을 읽습니다. 색 코드는 CI 로그와 에이전트 입력에서 잡음이 됩니다.

## D-12. `run()`은 `process`에 닿지 않는다

- **결정**: `run(argv, io)`가 종료 코드를 돌려주고, `process.exitCode`는 `cli.ts`에서만 정함.
- **이유**: 테스트에서 별도 프로세스 없이 명령을 그대로 부를 수 있습니다. 실제 git 저장소를 임시로 만들어 `scope`를 검사하는 테스트도 이 덕분에 빠릅니다.
